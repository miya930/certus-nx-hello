# 評価ボードの PHY を動かす試験用ファーム

Certus-NX Versa Evaluation Board の RGMII の Ethernet PHY を、SatCat5 のポートで動かす。
PHY を MDIO で設定し、固定のテストフレームを送り続けるだけの構成である。

このボードの OPN は LFD2NX-VERSA-B-EVN で、Ethernet PHY が未実装のまま出荷される。
動かすには、RGMII 側の U9 が実装されている必要がある。

## 構成

- PHY は DP83867IR で、RGMII の 1000 Mbps で使う。
- クロックは、ボードの 125 MHz の発振器 X5 から CLK_CUSTOMER2 として受ける。
  PLL を使わないため、この発振器をそのまま RGMII の送信クロックにする。
- 送信するフレームは、宛先がブロードキャスト、送信元が固定のローカル管理アドレス、EtherType が 0x88B5 である。
  中身は SatCat5 の生成器が作る擬似乱数で、1 フレームの本体は 256 バイトである。
- 押しボタン SW2 を押している間はリセットし、離すと PHY のリセットから始める。
- LED_0 は MDIO の設定が終わると点灯し、LED_1 は送信したフレーム数に合わせて点滅する。

## 設計

### 起動の順番

- PHY のリセットは 1 us 以上、リセットの解除から MDIO の操作までは 195 us 以上あける必要がある。
  電源投入からは 200 ms 以上あけるため、長いほうに合わせて待つ。
- 送信は、ポートが送信できる状態になってから始める。
  ポートがリセット中でも受け取りの合図は出るため、先に送るとフレームの先頭が失われる。

### PHY の設定

- MDIO では、RGMII を有効にし、送信と受信のクロックをデータに対してずらす設定にする。
  ずれの量は、どちらも 2.00 ns にする。
- 設定するレジスタは拡張レジスタ空間にあるため、アドレスを指定してから値を書く 4 回の書き込みで操作する。
- FPGA 側ではクロックをずらさず、ずれは PHY だけで作る。
  RGMII はどちらか一方でずらすことを求めるためである。
- PHY のアドレスはボードのストラップで決まる。
  評価ボードのユーザーガイドにはストラップの設定が書かれていないため、既定値の 0 にしてある。
  実機で応答がない場合は、`PHY_ADDR` を変えて確かめる。
- MDIO のデータ線は、FPGA が常に駆動する。
  読み出しをしないため、PHY がこの線を駆動することはない。

### SatCat5 を Nexus で使うための対処

- プラットフォーム層とパッチは `third_party/satcat5_nexus/` にあり、他のプロジェクトと共有する。
- `patches/port_rgmii.vhd.patch` は、10/100 Mbps 用のクロック分周にある剰余の演算を比較に書き換える。
  剰余は除算器になり、125 MHz に届かないためである。

## 検証

`make sim` のテストベンチで、次の動作を確認している。
テストベンチは、受信クロックとリンクの状態を出す PHY の代わりを含む。

- PHY のリセットが、必要な時間だけ 0 になってから解除される。
- MDIO の書き込みが、PHY のリセットを解除した後に始まる。
- MDIO で、決めた順番のレジスタに決めた値が書かれる。
  PHY のアドレスと、書き込みを表すビットもあわせて確認する。
- 送信したフレームに、プリアンブルと SFD が付く。
- フレームの宛先、送信元、EtherType、長さが決めたとおりで、FCS が正しい。
- MDIO の設定が終わると LED_0 が点灯する。

## 回路規模

LFD2NX-40-8BG256C で配置配線した結果を次に示す。

| 資源 | 使用量 |
|---|---|
| LUT | 682 |
| FF | 328 |
| 分散 RAM | 3 |
| I/O | 19 |

送信側のクロックの最大周波数は 272 MHz、受信側は 615 MHz で、どちらも 125 MHz に対して余裕がある。

合成のログには、ABC が出す `The network is combinational.` という警告が 1 件残る。
これは論理最適化の内部の知らせである。

## 実行方法

yosys、GHDL、nextpnr-nexus を含む OSS CAD Suite が必要になる。

```sh
git submodule update --init
make        # 合成と配置配線、ビットストリームの生成
make sim    # テストベンチ
make load   # SRAM に書き込む
```

- `make` は、`build/report.json` に資源ごとの使用数と最大動作周波数を出力する。
- `make sim` は、全てのテストを通過して `All tests finished.` を表示し、終了コード 0 で終わる。
- 実機での確認はまだしていない。

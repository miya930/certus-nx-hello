# heater_mpc

## 何を確認するか

格子に並べたチップ抵抗のヒーターとサーミスタを載せた FR4 の基板で、ヒーター同士が温度で影響し合う様子を確認する。
同じ基板をヒーターごとに独立した PID 制御と、全ヒーターをまとめて扱う MPC で温度制御したときの違いを確認する。
どちらもシミュレーションで、まだ実機はない。

## 必要な機材

PC だけで確認できる。
uv と、画面のビルドに Node.js の npm が必要になる。

## 実行方法

ヒーターの間隔を変えたときの、隣のセンサーへの影響の割合と応答時間を求める。

```sh
uv run projects/heater_mpc/thermal_sim.py
```

シミュレータの画面をブラウザで開く。
初回は画面のビルドに数十秒かかる。

```sh
uv run projects/heater_mpc/thermal_server.py
```

ブラウザが自動で開かないときは、`http://localhost:8765/` を開く。

## 期待する動作

`thermal_sim.py` は、ヒーターの間隔ごとの影響の割合を表示し、`build/thermal_sim.png` にグラフを出力する。

`thermal_server.py` を起動すると、Setup で条件を決めて Run simulation を押すまでは何も計算しない。
Setup では、格子の行数と列数、ヒーターの間隔、基板の端までの距離、ヒーターの外形、サーミスタの位置、基板の厚さ、銅箔の割合を決められる。
ヒーターの最大電力、PID の調整方法、MPC の制御周期、予測ホライズン、制御ホライズン、操作量の変化の重みも決められる。
PID は、ステップ応答から IMC の式で決める方法と、Kp、Ti、Td を直接与える方法を選べる。
Optimize を押すと、PID は Kp、Ti、Td を、MPC は操作量の変化の重みと制御ホライズンを、参照軌道に対する平均絶対誤差が最小になるように探索し、Setup に書き戻す。
探索には 1 分ほどかかる。
Run simulation と Optimize の実行中は、Setup の下に段階の名前と進み具合が表示される。
参照軌道は、段階ごとの開始時刻と各ヒーターの目標温度を表で編集でき、プリセットから選ぶこともできる。
昇温レートを与えると、目標温度が傾斜で変わる。
PID と MPC のタブでは、基板の温度分布の時間変化を再生ボタンとスライダーで見られる。
ヒートマップやグラフにカーソルを当てると、その位置とヒーターの温度と電力が表示される。
全サーミスタの温度と全ヒーターの電力を重ねたグラフ、選んだヒーターの PV、SV、MV をそろえたグラフ、制御器のパラメータが表示される。
Notes のタブには、熱モデル、参照軌道、PID 制御、MPC の解説と、使っている伝達関数モデルと状態空間モデル、MPC が制御周期ごとに行う演算が表示される。
解説と数式はシミュレーションを実行する前から読め、この基板での具体的な値は実行後にその場所へ差し込まれる。
PID のループ、移動ホライズン、カルマンフィルタの役割、MPC の 1 周期の演算の流れは、SVG のブロック図で示す。
状態空間モデルは、MPC が予測に使う粗いモデルの A、B、C の値をヒートマップと表で示し、JSON として保存できる。

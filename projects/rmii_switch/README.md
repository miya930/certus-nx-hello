# SatCat5 Ethernet スイッチ

LFD2NX-40 に SatCat5 のスイッチを実装し、RMII の PHY をつなぐ Ethernet スイッチとして使う。
VLAN と PTP を有効にし、どの RMII ポートからでも Ethernet フレームで設定を変えられる。
実機はまだないため、テストベンチと合成、配置配線で動作と回路規模を確認している。
PHY 基板の仕様は、[3 ポート Ethernet PHY 基板](../../hw/multi_phy_board/README.md) にまとめている。

## 構成

- RMII ポートの数は `PORT_COUNT` で決まり、既定は 4 である。
- スイッチコアは SatCat5 の switch_core で、ConfigBus 用の内部ポートを 1 つ加えて動かす。
- 全ポートとスイッチコアは、PHY 基板から来る 50 MHz の REF_CLK で動く。
  1 バイト幅のパイプラインなので、全ポート合計で 400 Mbps まで処理できる。
- 評価ボードの SYSTEM_25M_CLK は、REF_CLK が止まったことの検出と、PTP の基準に使う。

| ファイル | 内容 |
|---|---|
| `rmii_switch.vhd` | トップ |
| `rmii_switch_tb.vhd` | テストベンチ |
| `rmii_switch.pdc` | ピン割り当て |
| `nexus/` | SatCat5 のプラットフォーム部品の Nexus 向けの実装 |
| `nexus/sim/` | Nexus のプリミティブのシミュレーションモデル |
| `patches/` | ビルド時に SatCat5 に当てるパッチ |

## 設計

### 機能

- ConfigBus は、内部ポートにつないだ port_cfgbus が、EtherType が 0x5C01 の Ethernet フレームで受け付ける。
- PTP は、PLL を使わない coarse 方式で動かす。
  タイムスタンプの誤差は、RMII のクロックの半周期程度になる。
- coarse 方式は RMII のクロックが基準クロックの 2 倍より速いことを求めるため、SYSTEM_25M_CLK を 2 分周して基準にする。

### RMII のタイミング

- 送信データは、REF_CLK の立ち上がりで出す。
- 受信データは、I/O の遅延素子を通してから、I/O セルの入力レジスタで取り込む。
- 遅延量は、LAN8742A の出力の変化する期間と Certus-NX の入力レジスタの条件から求めた範囲の中央にする。
  求め方は `rmii_switch.vhd` のコメントにある。
- 計算に使った Certus-NX の値は専用のクロック入力ピンでの値で、PMOD の REF_CLK は一般のピンである。
  そのため、受信のマージンは実機で確認する必要がある。

### SatCat5 を Nexus で使うための対処

- `nexus/common_primitives_body.vhd` で、FIFO をメモリ方式にし、MAC テーブルの TCAM の LUT 幅を 6 にする。
  シフトレジスタ方式の FIFO は LFD2NX-40 に収まらず、LUT 幅 8 では MAC アドレスを重複して登録したためである。
- `patches/ptp_egress.vhd.patch` は、GHDL が合成できない、範囲が変わるスライスへの代入を書き換える。
- `patches/fifo_repack.vhd.patch` は、メモリ方式の FIFO で遅れるメタデータを、レジスタで LAST とそろえる。
- `patches/switch_core.vhd.patch` は、シミュレーションで同じエッジのデータを取り込まないよう、ポートのクロックを直接渡す。
- `patches/port_rmii.vhd.patch` は、受信データに入力遅延を入れる設定を追加する。

## 検証

`make sim` のテストベンチで、次の動作を確認している。

- ConfigBus で、読み出し専用のレジスタからスイッチの構成が読める。
- 未学習の宛先へのフレームは、送信元以外の全ポートに送られる。
- 学習した宛先へのフレームは、そのポートにだけ送られる。
- PTP の Sync は、スイッチ内の滞在時間が correctionField に加えられ、FCS が付け直されて送られる。
- VLAN のポートマスクに含まれないポートには、そのタグのフレームが送られず、出力ではタグが取り除かれる。

Nexus のプリミティブのモデルは、技術ノートに書かれた範囲で作っており、出力の遅延は実機と異なる可能性がある。

## 回路規模

### 測定条件

- デバイスは LFD2NX-40-8BG256C である。
- SatCat5 は release/2.9.0 に、`patches/` のパッチを当てたものを使った。
- ツールは OSS CAD Suite 2026-09-12 に含まれる yosys 0.69+24、nextpnr-0.11.1-26、GHDL 7.0.0-dev を使った。
- スイッチの構成は `rmii_switch.vhd` のとおりで、VLAN と PTP を有効にし、ConfigBus は内部ポートから操作する。
- ポート数は RMII ポートの数で、ConfigBus 用の内部ポートを含まない。
- 使用量は、`make PORT_COUNT=<N>` で配置配線したときに nextpnr-nexus が報告した値である。
- 内訳は、合成後のネットリストをセル名の階層で集計した。
  LUT は配置時の LUT スロット数に換算し、LUT4 を 1、WIDEFN9 と CCU2 を 2、DPR16X4 を 4 と数えた。
  そのため、内訳の合計は nextpnr-nexus の報告値と少し異なる。
- 数値は、受信データに入力遅延を入れる前に測った。
  入力遅延を入れた後の 4 ポートでは、LUT が 22,558 になった。

### ポート数ごとの使用量

LFD2NX-40 の総量は、LUT と FF がそれぞれ 32,256、EBR が 84、分散 RAM が 4,032 である。

| ポート数 | LUT | FF | EBR | 分散 RAM | REF_CLK の最大周波数 | 配置配線 |
|---|---|---|---|---|---|---|
| 2 | 15,219 (47%) | 9,805 (30%) | 46 (54%) | 666 (16%) | 87.1 MHz | 成功 |
| 3 | 18,841 (58%) | 11,972 (37%) | 51 (60%) | 864 (21%) | 83.2 MHz | 成功 |
| 4 | 22,503 (69%) | 14,153 (43%) | 58 (69%) | 1,065 (26%) | 86.6 MHz | 成功 |
| 5 | 26,107 (80%) | 16,326 (50%) | 63 (75%) | 1,263 (31%) | - | 失敗 |

REF_CLK のクロック網は、report.json では `cfg_cmd[0]` という名前で報告される。

### ポート数の上限

ポート数の上限は 4 である。
5 ポートでは、LUT の使用率が 80% の時点で配置に失敗した。

Nexus では LUT と FF を組にして配置するため、クロック、イネーブル、リセットの組み合わせが異なる FF は同じ場所に置けない。
4 ポートの構成では、この組み合わせが 1,213 種類あり、そのうち 638 種類は FF が 2 個以下だった。
LUT の使用率が 80% に近づくと、条件に合う置き場所がなくなったと考えられる。

### RMII ポート 1 つあたりの増加

ポート数を 1 つ増やしたときの増加量は、2 から 5 ポートの測定でほぼ一定だった。

| 資源 | 増加量 |
|---|---|
| LUT | 約 3,600 |
| FF | 約 2,170 |
| EBR | 5 から 7 |
| 分散 RAM | 約 200 |

4 ポート構成のポート 0 の内訳を次に示す。

| 回路 | LUT | FF |
|---|---|---|
| 入力側のパケット FIFO | 956 | 425 |
| 出力側のパケット FIFO | 905 | 515 |
| PTP の出力処理 | 558 | 267 |
| PTP の入力処理 | 238 | 266 |
| FCS の検査 | 248 | 134 |
| VLAN タグの除去と付加 | 271 | 147 |
| RMII の送受信 | 212 | 184 |
| 出力フレームの調整 | 151 | 79 |
| PAUSE フレームの処理 | 139 | 76 |
| 合計 | 約 3,700 | 約 2,160 |

### ConfigBus の内訳

4 ポート構成での ConfigBus の内訳を次に示す。

| 回路 | LUT | FF |
|---|---|---|
| 内部ポートのスイッチ処理 | 3,043 | 1,767 |
| port_cfgbus | 693 | 305 |
| 各ブロックの設定レジスタ | 約 560 | 約 1,417 |
| 合計 | 約 4,300 | 約 3,500 |

SatCat5 の switch_core は、パケット FIFO、PTP、VLAN の回路を全てのポートに同じように持たせる。
そのため、ConfigBus 用の内部ポートも RMII ポートとほぼ同じ規模になる。
設定レジスタの値は、セル名に cfg を含むものを数えた概算である。

### スイッチ全体で共有する回路

4 ポート構成で、MAC パイプラインのうち規模の大きい回路を次に示す。

| 回路 | LUT | FF |
|---|---|---|
| MAC アドレスの学習と検索 | 2,127 | 1,533 |
| PTP の処理 | 934 | 855 |
| VLAN の帯域制限 | 628 | 278 |
| ConfigBus のレジスタ | 163 | 200 |
| MAC テーブルの読み出し | 157 | 180 |
| VLAN のポート設定 | 83 | 98 |

### 機能を外した場合

4 ポート構成で、switch_core の VLAN と PTP を外して測定した。

| 構成 | LUT | FF | EBR | 分散 RAM |
|---|---|---|---|---|
| VLAN と PTP を有効 | 22,503 (69%) | 14,153 (43%) | 58 (69%) | 1,065 (26%) |
| VLAN を無効 | 19,958 (61%) | 12,301 (38%) | 42 (50%) | 895 (22%) |
| VLAN と PTP を無効 | 9,848 (30%) | 5,746 (17%) | 41 (48%) | 65 (1%) |

- VLAN を外すと、LUT が約 2,500 減る。
- VLAN を外した状態から PTP も外すと、LUT がさらに約 10,100 減る。
- switch_core は PTP の有無を全ポートで 1 つの設定として持つため、一部のポートだけ PTP を有効にすることはできない。
  一部のポートだけに PTP を持たせるには、SatCat5 の変更が必要になる。
- PTP の回路のうち、MAC パイプラインで共有する分は約 930 である。
  残りを内部ポートを含む 5 つのスイッチポートで割ると、PTP は 1 ポートあたり約 1,800 の LUT を使う概算になる。

## 実行方法

PC だけで確認でき、yosys、GHDL、nextpnr-nexus を含む OSS CAD Suite が必要になる。

```sh
git submodule update --init
make PORT_COUNT=4   # 合成と配置配線
make sim            # テストベンチ
```

- `make PORT_COUNT=4` は、`build/ports4/report.json` に資源ごとの使用数と、クロックごとの最大動作周波数を出力する。
  REF_CLK の最大周波数が 50 MHz を上回ることを確認する。
- `make sim` は、全てのテストを通過して `All tests finished.` を表示し、終了コード 0 で終わる。
- ボードに合わせたピン割り当てをしていないため、まだ実機には書き込めない。
